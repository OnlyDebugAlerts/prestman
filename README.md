# Prestman

Нативный настольный клиент для HTTP, HTTPS, gRPC и GraphQL на Rust 1.100.0 и GPUI Kit 0.10.0.

Выберите метод и укажите URL. В каждом новом запросе уже включён заголовок `Content-Type: application/json`; его можно изменить или отключить в **Headers**. Тело запроса вводится в первой вкладке **Body** с подсветкой синтаксиса JSON и комментариев `// …` / `/* … */`; кнопка с иконкой форматирования (**Format JSON** в подсказке) форматирует JSON, сохраняя комментарии. В сохранённом запросе комментарии остаются, а при отправке JSON-тела удаляются; строки вроде `https://example.com` сохраняются без изменений. Следом находится вкладка **Authorization** с Bearer Token и Basic Auth. Выбранный способ формирует заголовок `Authorization` при отправке. Вкладка **Query** показывает параметры URL отдельными парами **Name** и **Value**. При вставке URL параметры заполняются автоматически, а правки в таблице обновляют URL. Во вкладке **Headers** каждый заголовок тоже имеет отдельные поля имени и значения. Флажок слева от строки в **Query** и **Headers** включает или отключает её отправку. Отключённые строки остаются в таблице, доступны для редактирования и сохраняются вместе с запросом; отключённые query-параметры исключаются из URL. Справа отображаются статус, время, размер, заголовки и полное тело ответа. JSON форматируется и отображается с подсветкой синтаксиса.

На macOS логотип Prestman отображается в Dock и системном трее. Меню иконки в трее содержит **Show Prestman** (возвращает окно, в том числе свёрнутое) и **Quit Prestman**. Исходный логотип и его уменьшенная версия находятся в `assets/prestman-logo.png` и `assets/prestman-tray.png`; описание генерации — в `assets/logo-generation.md`.

Сочетание `⌘S` / `Ctrl+S` сохраняет выбранный запрос в локальный `requests.json` в каталоге данных приложения. При обычном закрытии окна и выходе через меню, трей или `⌘Q` приложение автоматически сохраняет все запросы и черновики, включая URL, Body, Authorization, Headers, Query и оба скрипта. После перезапуска они восстанавливаются. Корректные несохранённые правки открытого редактора переменных и названия коллекции тоже сохраняются. Если сохранение при закрытии окна не удалось, окно остаётся открытым с сообщением об ошибке; прежний файл сохраняется.

Кнопка-иконка **Scripts** (`</>`) внизу справа, рядом с **Console** и **Tests**, открывает JavaScript-скрипты **Pre-request** (до подстановки переменных и отправки) и **Post-response** (после ответа). Поддерживаются `pm.variables`, `pm.environment`, `pm.globals`, `pm.collectionVariables`, изменение отправляемого запроса, `pm.sendRequest`, `pm.response`, `pm.test`, `pm.expect` (Chai), `CryptoJS` / `require('crypto-js')` и `console.log`. Результаты открываются кнопками-иконками **Tests** (галочка) и **Console** (терминал) внизу справа в панели ответа. Сразу после **Body** находится **Visualizer**: `pm.visualizer.set(template, data)` отображает Handlebars-шаблон как HTML с CSS и JavaScript. [Примеры Visualizer](docs/visualizer.md). **Settings → Environment** открывает общие переменные окружения. Скрипты сохраняются вместе с запросом. [Примеры и поддерживаемый API](docs/scripts.md). Для проверки обоих этапов без внешних сервисов есть [готовые тестовые скрипты и локальный сервер](examples/scripts/README.md).

**+** в правом верхнем углу сайдбара открывает меню создания HTTP, gRPC и GraphQL-запросов или коллекции. ПКМ по коллекции или папке → **New request** создаёт запрос внутри неё. Новый запрос также создаётся через `⌘N` / `Ctrl+N`. ПКМ по коллекции или папке → **New folder** создаёт вложенную папку. Поле **Folder name** появляется сразу под выбранным родителем с соответствующим отступом, а родитель раскрывается и прокручивается к форме. `Enter` создаёт папку, `Esc` отменяет. Коллекция обозначается иконкой библиотеки, папки — прежней иконкой папки. Перетащите запрос на коллекцию или папку либо выберите путь через **Move to** в контекстном меню запроса. Папки можно перетаскивать внутрь других папок и коллекций; перемещение в собственное поддерево запрещено. Двойной клик по папке открывает переименование, **Variables** открывает её переменные, **Delete** удаляет всё её поддерево с запросами. Для перемещения обратно выберите **Ungrouped** в меню **Move to**. Запросы вне коллекций отделены горизонтальной линией; если таких запросов нет, линия скрыта. Клик по названию коллекции сворачивает и раскрывает её, двойной клик открывает переименование. В контекстном меню коллекции можно создать запрос, открыть переменные или удалить её пунктом **Delete** вместе со всеми её сохранёнными запросами и черновиками. Коллекции и принадлежность сохранённых запросов сохраняются сразу.

Кнопка настроек внизу левой панели открывает меню **Settings**; пункт **Globals** открывает глобальные переменные. Пункт **Variables** в контекстном меню коллекции открывает её переменные. Укажите имя без скобок и значение, затем нажмите **Save** (`⌘S` / `Ctrl+S`). **Cancel** отменяет правки. Флажок позволяет отключить переменную. В таблицах переменных, **Query** и **Headers** всегда есть пустая строка: начните вводить имя или значение, и следующая строка появится автоматически. Пустые строки не сохраняются.

В строке URL шаблоны `{{name}}` подсвечиваются оранжевым, а path-параметры `:name` — фиолетовым. Подсветка обновляется при вводе и редактировании Query. При наведении на `{{name}}` в URL, Headers, Query, Authorization, Body, Scripts и значениях переменных появляется подсказка с текущим значением и источником. В URL подсказка работает также для `:name`. В карточку можно перевести курсор: значение доступно для выделения и копирования через `⌘C` / `Ctrl+C`, а кнопка **Copy value** копирует полное значение целиком без обрезки. `Esc` или клик вне карточки закрывает её; при выделении текста она остаётся открытой. Вложенные ссылки на переменные раскрываются; неизвестные и циклические ссылки показывают ошибку.

Используйте `{{name}}` в URL, query-параметрах, именах и значениях заголовков, Body, Bearer Token и полях Basic Auth. Например, глобальная `base_url = https://api.example.com` позволяет отправить запрос на `{{base_url}}/users`. Переменная коллекции перекрывает одноимённую глобальную; переменная папки — значения родителей, переменная окружения — все эти уровни. Локальные переменные из pre-script имеют наивысший приоритет; запросы из **Ungrouped** не используют переменные коллекций. Имена чувствительны к регистру. Значения могут ссылаться на другие переменные. Неизвестная переменная или циклическая ссылка показывают ошибку до отправки. Подстановка выполняется только при отправке: шаблоны запросов сохраняются без изменений, а переменные сохраняются локально между запусками.

Двойной клик по запросу открывает редактирование имени прямо в строке сайдбара: `Enter` или потеря фокуса завершает переименование, `Esc` отменяет его. **Copy link** копирует URL, **Copy** копирует запрос как JSON, а **Duplicate** создаёт черновик в той же коллекции. Для HTTP верхняя строка с названием запроса и кнопкой Save убрана; работают `⌘S` / `Ctrl+S` и сохранение при закрытии.

Ссылки `http://` и `https://` в теле и заголовках ответа открываются в браузере по `⌘ + ЛКМ` на macOS (`Ctrl + ЛКМ` на Windows/Linux). В JSON поддерживаются экранированные слеши и Unicode-последовательности в URL.

**ПКМ по HTTP-коллекции → Export collection** сохраняет текущие запросы и черновики в [Postman Collection v2.1](https://schema.postman.com/json/collection/v2.1.0/docs/index.html). Экспорт включает папки, переменные коллекций и папок, тела запросов, авторизацию, скрипты и отключённые параметры.

## Импорт Swagger / OpenAPI

Откройте **Settings → Import Swagger / OpenAPI** внизу сайдбара. Кнопка **Choose File** загружает спецификацию JSON или YAML. Чтобы загрузить её по сети, вставьте прямую ссылку на документ (например, `https://api.example.com/v3/api-docs`) и нажмите **Import URL**.

Prestman создаёт и сохраняет отдельную коллекцию из Swagger 2.0 или OpenAPI 3.0–3.2. Каждый сегмент пути образует уровень вложенности, как в стратегии [Paths конвертера Postman](https://github.com/postmanlabs/openapi-to-postman/blob/develop/OPTIONS.md). Например, запросы `/api/v1/accounts/{id}` попадают в `api → v1 → accounts → {id}`. Адреса серверов доступны в переменных коллекции `baseUrl`, `baseUrl2` и далее. В запросах заполняются параметры пути, query, заголовки, примеры тела и настройки поддерживаемой авторизации. Для схем с Basic, Bearer или API key задайте значения переменных `auth_…` через **Variables**.

Внешние `$ref` могут ссылаться на файлы внутри папки спецификации или на документы с того же источника HTTP(S). Сохранённые примеры ответов и файловые вложения пока за пределами импорта.

В поле URL можно вставить команду **cURL**, в том числе многострочную из **Copy as cURL** в браузере. Prestman автоматически заполнит метод, URL, Query, Headers, Authorization и Body текущего запроса. Например:

```bash
curl 'https://api.example.com/items?limit=10' \
  -H 'Authorization: Bearer token' \
  --json '{"title":"Example"}'
```

Поддерживаются кавычки и переносы Bash, `-X`, `-H`, `--data-raw`, `--data-binary`, `--data-urlencode`, `--json`, `-G`, `-I`, cookies, Basic и Bearer. Имя, папка и скрипты текущего запроса сохраняются; отправка выполняется кнопкой **Send**. Команда разбирается без запуска shell. Файлы, multipart и неподдерживаемые опции показывают ошибку, сохраняя прежний запрос.

## gRPC

1. Нажмите ПКМ в сайдбаре, коллекции или папке и выберите **New request → gRPC Request**.
2. Введите адрес сервера, например `localhost:50051` для локального сервера или `grpcs://api.example.com:443` для TLS. Значок замка слева от адреса переключает TLS. Prestman загружает методы через server reflection после ввода адреса. Для ручной загрузки нажмите **Service definition → Load methods**. На сервере без reflection откройте **Service definition → Import .proto** и выберите исходный `.proto` или скомпилированный descriptor set.
3. Выберите RPC-метод. Во вкладке **Message** введите Protobuf JSON или нажмите **Use Example Message**. Во вкладке **Metadata** можно указать текстовые значения и бинарные значения в Base64 для ключей с суффиксом `-bin`. Работают переменные `{{name}}`, Basic Auth и Bearer Token.
4. Нажмите **Invoke**. Для client streaming и bidirectional streaming кнопка **Send** отправляет текущее сообщение, **End Streaming** закрывает исходящую часть потока, а **Cancel** отменяет вызов. В **Messages** видны отправленные и полученные сообщения. Отдельные вкладки показывают metadata и trailers.

В **Service definition** доступны проверка сертификата, имя сервера, deadline и размер ответа. В **Scripts** доступны этапы **Before invoke**, **On message** и **After response**. В проверках можно использовать `pm.message.data`, `pm.response.statusCode`, `pm.response.metadata`, `pm.response.trailers` и `pm.response.messages`.

**Export gRPC request** в меню запроса создаёт файл `*.request.yaml`. **Export collection** для коллекции с gRPC создаёт папку Postman v3, в которой могут быть и HTTP-запросы. При экспорте локальной схемы YAML ссылается на исходный `.proto` относительным путём. Prestman сохраняет скомпилированную схему вместе с запросом для локального запуска. В экспорте поддерживаются reflection и локальные определения. [Формат Postman v3](https://learning.postman.com/latest-v-12/docs/use/use-collections/collections-schemas)

## GraphQL

Нажмите **+ → GraphQL Request**, укажите URL и введите запрос или мутацию во вкладке **Query**. Во вкладке **Variables** задайте переменные операции в виде JSON-объекта. Для документа с несколькими операциями укажите имя нужной операции над редактором.

Prestman отправляет GraphQL по HTTP POST. Работают заголовки, Basic/Bearer-авторизация, шаблоны `{{name}}` и скрипты до отправки и после ответа. **Schema → Load schema** загружает поля и типы через introspection с текущими заголовками и авторизацией. GraphQL-запросы и коллекции с ними экспортируются в формате Postman v3. Подписки через WebSocket пока за пределами поддержки.

## Горячие клавиши

### Вкладки и поиск

| Действие | macOS | Windows и Linux |
| --- | --- | --- |
| Создать запрос в новой вкладке | `⌘T` или `⌘N` | `Ctrl+T` или `Ctrl+N` |
| Закрыть активную вкладку | `⌘W` | `Ctrl+W` |
| Следующая вкладка | `Control+Tab` | `Ctrl+Tab` |
| Предыдущая вкладка | `Control+Shift+Tab` | `Ctrl+Shift+Tab` |
| Найти и открыть запрос | `⌘K` | `Ctrl+K` |

Вкладки переключаются по кругу в порядке верхней полосы. При закрытии вкладки черновик остаётся в списке запросов. При обычном выходе Prestman сохраняет открытые вкладки, их порядок и активную вкладку. Локальные вкладки восстанавливаются при запуске, командные — при повторном открытии соответствующего пространства.

В поиске введите часть названия, метода (например, `POST`), URL или пути папки. Поиск работает и по свёрнутым коллекциям. `↑` и `↓` выбирают результат, `Enter` открывает его и переводит фокус в поле URL. `Esc` очищает поиск, а при пустом поле закрывает окно.

### Фокус и выполнение запросов

| Действие | macOS | Windows и Linux |
| --- | --- | --- |
| Перейти к списку коллекций и запросов | `⌘1` | `Ctrl+1` |
| Перейти к URL или адресу gRPC | `⌘L` | `Ctrl+L` |
| Перейти к телу запроса, GraphQL Query или gRPC Message | `⌘2` | `Ctrl+2` |
| Перейти к телу ответа или сообщениям активного gRPC-потока | `⌘3` | `Ctrl+3` |
| Отправить запрос | `⌘Enter` | `Ctrl+Enter` |
| Сохранить запрос или значения в открытом редакторе переменных | `⌘S` | `Ctrl+S` |
| Завершить приложение с сохранением | `⌘Q` | — |

### Коллекции и папки

Перейдите в левую панель через `⌘1` или `Ctrl+1`.

| Клавиша | Действие |
| --- | --- |
| `↑` / `↓` | Переместить выделение по видимым строкам |
| `Home` / `End` | Перейти к первой или последней видимой строке |
| `→` | Раскрыть коллекцию или папку либо перейти к её первому элементу |
| `←` | Свернуть открытую папку или перейти к родительской папке |
| `Enter` | Открыть выделенный запрос или свернуть либо раскрыть группу |

Например, чтобы открыть и отправить запрос без мыши, нажмите `⌘K` или `Ctrl+K`, введите часть названия, нажмите `Enter`, затем `⌘Enter` или `Ctrl+Enter`.

## Автообновления

Prestman проверяет последний опубликованный стабильный [релиз GitHub](https://github.com/OnlyDebugAlerts/prestman/releases) через несколько секунд после запуска и затем каждые шесть часов. Если доступна новая версия для вашей ОС и архитектуры, рядом с названием приложения появляется **Update**. Проверить вручную можно через **Settings → Check for updates**; там же указана текущая версия.

**Update** скачивает, проверяет и устанавливает обновление в фоне. После установки кнопка меняется на **Restart**. Перезапуск происходит только по нажатию и сохраняет черновики, переменные и открытые вкладки. Пока идёт установка, закрытие приложения отложено. При ошибке можно повторить попытку или открыть **Releases**. Ошибка фоновой проверки не мешает работе.

Поддерживаются архивы из официальных релизов: отдельный исполняемый файл Windows/Linux и целый `Prestman.app` на macOS. Каталог установки должен быть доступен для записи; на macOS сначала переместите приложение из архива в постоянное место. Установки через сторонние пакетные менеджеры этим механизмом не поддерживаются.

Релизный workflow встраивает версию из тега `vX.Y.Z` через `PRESTMAN_RELEASE_TAG`. Чтобы обновление стало доступно, опубликуйте черновик как стабильный релиз. Prestman скачивает выбранный архив, сверяет SHA-256 из GitHub и на macOS проверяет целостность подписи `.app`. Источник обновлений — официальный репозиторий GitHub по HTTPS. Для сборки вне workflow используется версия из `Cargo.toml`.

## Сборка и запуск

Установите [rustup](https://rust-lang.org/tools/install/). `rust-toolchain.toml` задаёт нужную версию Rust. Для нативной сборки нужны системные инструменты. [Документация GPUI Kit](https://gpui-kit.com/docs/installation/)

- **macOS 15 и новее** — `xcode-select --install`.
- **Windows 10 и новее** — Rust для MSVC, Visual Studio Build Tools с профилем **Desktop development with C++**, Windows SDK с `fxc.exe` для релизной сборки и CMake в `PATH`.
- **Linux (Ubuntu)** — команды ниже. Для запуска нужен графический сеанс X11/XWayland и рабочий драйвер Vulkan.

```bash
sudo apt update
sudo apt install build-essential clang pkg-config libfontconfig-dev libwayland-dev \
  libxkbcommon-x11-dev libx11-xcb-dev libssl-dev libzstd-dev libvulkan1 \
  libgtk-3-dev libwebkit2gtk-4.1-dev
```

Запустите приложение из папки проекта.

```bash
cargo run --locked --release
```

Тесты выполняются командой `cargo test --locked`. Проверка сборки и тестов для трёх ОС описана в GitHub Actions.

## Командные коллекции

Нажмите **Cloud** над списком запросов, войдите или создайте аккаунт, затем выберите **Create workspace**. Нажмите **Open**, чтобы работать в командном пространстве. Кнопка **Team workspace** открывает состав участников. Владелец может создать код приглашения для подтверждённого email, изменить роль или отозвать доступ. Передайте код коллеге. После входа он вводит его в **Cloud → Accept invitation**, а затем открывает пространство. Приглашение действует семь дней и используется один раз.

- **Owner** управляет доступом и редактирует коллекции.
- **Editor** создаёт и редактирует коллекции, папки и запросы.
- **Viewer** просматривает коллекции и запускает запросы. Свои правки он может сохранить как локальный черновик.

Чтобы опубликовать существующую коллекцию, вернитесь через **Team workspace → Back to local** и в контекстном меню коллекции выберите **Publish to cloud…**. **Preview shared data** показывает содержимое перед публикацией. В публикации значения переменных коллекции очищаются, а литералы в поддерживаемых полях авторизации, заголовках и query заменяются ссылками на переменные. Значения для запуска задаются в **Settings → Environment** командного пространства. Тела запросов и скрипты входят в публикацию, поэтому их тоже можно проверить в предпросмотре.

В командном пространстве `⌘S` / `Ctrl+S` ставит сохранённую правку в очередь синхронизации. Клиент проверяет обновления примерно раз в четыре секунды. При сбое связи очередь и черновики остаются на устройстве. При конфликте можно сравнить правки, открыть облачную версию или сохранить свою версию запроса копией. Общие переменные редактируются через **Variables** коллекции. Запросы и скрипты выполняются на компьютере участника.

### Свой сервер

Запустите бэкенд одной командой Docker Compose через `python3 self-host/manage.py up`. На VPS можно указать домен для автоматического HTTPS. Создайте аккаунты на сервере, затем передайте участникам URL и публичный ключ. Они сохраняют их в **Cloud** и входят из приложения. [Инструкция для своего сервера](self-host/README.md)

### Управляемый Supabase

1. Создайте проект [Supabase](https://supabase.com/docs/guides/auth). Включите вход по email и паролю и подтверждение email. Для подтверждения адресов участников настройте [SMTP](https://supabase.com/docs/guides/auth/auth-smtp) и укажите Site URL проекта, который откроется после подтверждения.
2. Примените [миграцию](supabase/migrations/202611200001_team_workspaces.sql) к PostgreSQL проекта через SQL Editor или CLI Supabase.
3. В **Cloud** укажите URL проекта и клиентский publishable key, нажмите **Save server**, затем войдите. Один и тот же проект нужен всем участникам. Если сервер уже выбран, нажмите **Change server** на экране входа.

При запуске из терминала можно задать настройки по умолчанию.

```sh
PRESTMAN_CLOUD_URL=https://PROJECT_REF.supabase.co \
PRESTMAN_CLOUD_KEY=sb_publishable_... \
cargo run --locked
```

Те же переменные можно передать при сборке готового приложения. Сохранённые в **Cloud** настройки имеют приоритет. Клиентская сессия хранится в памяти. После перезапуска приложения потребуется вход.

[SQL-тест](supabase/tests/team_workspaces.sql) можно выполнить через `psql` в тестовой базе после применения миграции. Он проверяет приглашения, роли, конфликтующие и независимые правки, повтор сохранения и отзыв доступа. Тестовые данные откатываются.
